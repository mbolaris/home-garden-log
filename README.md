# Home Garden Log

Welcome to the **Home Garden Log** repository. This project serves as a central
place to track all activities, observations and current information about a
home garden located in Solana Beach, California (near the Pacific coast).  Keeping clear records helps
identify patterns, successes, challenges and ideas for improvement over time.

This repository contains two key files:

* **historical_log.md** – A chronological journal of all notable events.
  Each entry records what happened, when it happened, and any notable
  observations or decisions. The log is intended to be an ever‑growing
  archive – nothing is removed from it, and new entries are always
  appended at the bottom.

* **current_state.md** – A snapshot of the garden right now.  This file
  summarises what is planted where, how each plant is performing, and any
  immediate tasks that need attention.  When the current state changes
  significantly – for example, plants are harvested, new seeds are sown, or
  pests appear – update this file to reflect the new situation.  Past
  snapshots can be copied into the historical log if you want to preserve
  them for future reference.

## Usage

1. **Record historical events**
   - Add new entries to `historical_log.md` using the markdown heading
     format `### YYYY‑MM‑DD` followed by a description of what happened.
     Include as much detail as possible – crop varieties, quantities,
     weather conditions, problems encountered and what actions were taken.
   - Keep the entries in chronological order, with the newest entry at the
     bottom of the file.

2. **Update the current state**
   - Edit `current_state.md` whenever there are changes in the garden.  Use
     tables, lists or diagrams to describe the layout, plants, growth
     stages, and tasks to be done.  Feel free to include photos (saved in
     an `images/` directory and referenced here using Markdown).
   - When creating a new snapshot, you can copy the previous contents of
     this file into `historical_log.md` (as a dated entry) before
     overwriting it.

This repository is intentionally kept simple so that it can be edited from any
text editor or Git interface.  If you are using GitHub, consider creating a
branch and opening a pull request when making changes so that you can review
differences and maintain a history of edits.
